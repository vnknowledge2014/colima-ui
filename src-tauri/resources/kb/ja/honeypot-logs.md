# ハニーポットのログを読む

## 唯一の原則

ハニーポットのログ行は、フィルタで除去すべきノイズではありません。ハニーポット
には正当な接続が来ないため、すべての行は「触れられるはずのないサービスに何かが
触れた」ことを意味します。量はチューニングで消すべき問題ではなく、シグナルとして
扱ってください。

これはアプリケーションログの読み方とは正反対であり、ハニーポットを動かす価値が
ある理由でもあります。

## 読んだ内容に基づいて行動する前に

ハニーポットのログに記録されるのは攻撃者の自己申告であり、その申告は簡単に偽装
できます。

- **送信元アドレスはしばしば詐称、あるいは踏み台です。** 到達してきた IP は、
  多くの場合、侵害された第三者であって攻撃者本人ではありません。報復せず、逆に
  スキャンし返さず、簡単に取り消せないブロックリストに載せないでください。
- **ハニーポットに取り込まれたファイルは敵性ファイルです。** Cowrie は攻撃者が
  ダウンロードしようとしたものを保存します。好奇心で自分のマシン上で開いたり、
  実行したり、展開したりしないでください。
- **生ログを公開しないでください。** 第三者のアドレスや、実際の漏洩から使い回さ
  れた認証情報が含まれることがあります。共有する前に伏せ字にしてください。

## ColimaUI で監視する

これらの記事のハニーポットは通常の Compose プロジェクトなので、すでにある機能が
そのまま使えます。

- **Compose ページ** — プロジェクトを見つけ、サービスを開き、アプリを離れずに
  ログを読めます。進行中のセッションを見る最短の方法です。
- **Containers ページ** — ハニーポットが実際に稼働していること、どれだけ動いて
  いるかを確認できます。
- **Activity ページ** — CPU とメモリの推移。ハニーポットが突然本当に CPU を使い
  始めたら、それ自体が調査に値します。ノックする以上のことが起きているという
  ことです。

## 何を見るべきか

**試された認証情報。** 攻撃者が使うユーザー名とパスワードの一覧は、相手があなた
を何だと思っているかを示します。ルーターの初期パスワードばかりなら無差別スキャン
です。実際のアプリケーションのユーザー名が現れたなら、狙われています。

**実行されたコマンド。** Cowrie では、ログイン直後の最初のコマンドが最も情報量が
あります。`uname -a` は偵察です。IP アドレスへの `wget` や `curl` はペイロードを
取得しようとする動きであり、取得先の URL はそのまま行動に移せる具体的な情報です。

**繰り返し。** 同じ送信元アドレスが戻ってくるのは、一度きりの接続が千件あるのとは
異なります。後者はインターネットの背景ノイズ、前者はあなたに気づいた誰かです。

**時間帯。** サービスを公開した数分後にヒットが集中するのは、無差別スキャンに
見つかったということです。公開アドレスでは普通のことで、あなたの安全性について
は何も語りません。インターネットが忙しいというだけです。

## 出力を残す

どちらのハニーポットも、人間が読む形式と並行して構造化 JSON を書き出します。

```bash
# Cowrie — 取り出してからホスト側で読みます。
docker compose -f cowrie-compose.yml cp \
  cowrie:/cowrie/cowrie-git/var/log/cowrie/cowrie.json ./cowrie.json
tail -20 cowrie.json
```

`exec cat` ではなく `cp` を使うのは好みの問題ではありません。Cowrie のイメージ
にはシェルも `cat` も含まれていないため、`exec` は
`executable file not found` で失敗します。`cp` はデーモン経由で動作し、コンテナ
内には何も必要としません。

デモを超えて動かし続けるなら、そのファイルを定期的に外へ退避してください。
コンテナログはローテートされ、ボリュームは削除されます。記録は残って初めて価値
を持ちます。

## いつ止めるか

仕組みを学ぶために始めたのなら、セッションを最初から最後まで一度見終えた時点で
止めてください。誰も出力を読まないまま動き続けるサービスは検知ではありません。
ネットワークに応答するだけの余計なものが、マシンに一つ増えているだけです。
