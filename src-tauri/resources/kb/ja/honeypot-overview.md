# Colima 上のハニーポット

## ハニーポットとは

ハニーポットは、攻撃されるためだけに存在するサービスです。正当な通信が接続して
くることは一切ないため、記録されるすべての接続は、定義上、想定外のものです。
これがすべての要点です。通常のトラフィックによる誤検知が起きないのは、そもそも
通常のトラフィックが存在しないからです。

コンテナはハニーポットをローカルで実行しやすくします。それぞれが独自のファイル
システムを持つ使い捨てのプロセスであり、Colima はすでにそれらを VM の中に閉じ
込めています。

## 実行する二つの目的は大きく異なる

どちらを行っているのかを明確にしてください。リスクの性質が正反対だからです。

**学習のため。** 自分のマシン上で localhost にバインドして実行し、自分で接続し
てログの見え方を確認します。悪意ある通信は届きません。これは安全で、ここに並ぶ
記事が説明しているのはこの使い方です。

**検知のため。** 本来何も触れないはずのネットワークに配置し、反応があれば本物の
シグナルとして扱います。これは実際に有用ですが、実際に重大な結果も伴います。
近づく前に下の警告を読んでください。

## 実ネットワークに公開する前に

これは形式的な注意ではありません。

- **公開インターネット上のハニーポットは、あなたの IP アドレスに悪意ある通信を
  引き寄せます。** それがその役目です。あなたは自ら標的になることを選んでおり、
  その通信はあなたが興味を失っても止まりません。
- **まず職場のポリシーを確認してください。** 企業ネットワークでは、インフラを
  装うサービスの実行は、意図が防御目的であってもポリシー違反になり得ます。
  事後ではなく事前に確認してください。
- **ホスティング事業者にも規約があります。** 明確に禁止するところも、事前申告を
  求めるところもあります。
- **侵害されたハニーポットは足がかりになります。** これらのサービスは意図的に
  脆弱です。突破された場合、攻撃者はあなたが配置したネットワークの内側にいます。

これらの記事の compose ファイルがすべて `127.0.0.1` にバインドしているのはその
ためです。`0.0.0.0` に変更するなら、それは一つの決断です。意識的に行ってください。

## どこから始めるか

まず **Cowrie による SSH ハニーポット** を読んでください。ログが最も読みやすく、
コマンド一つで自分でトラフィックを発生させられるため、先に進むかどうかを決める
前に一連の流れを確認できます。

**OpenCanary によるおとりサービス** は、実際の検知での使われ方に近いものです。
何かが触れるまで静かなままです。

**ハニーポットのログを読む** は、出力が得られた後に何をするかを扱います。
