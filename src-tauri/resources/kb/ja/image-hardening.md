# コンテナイメージを堅牢にする

## セキュリティページが見ているもの

別々の二つの問いです。**既知の脆弱性**は Trivy が答えます。イメージ内のパッケージ
に公開済みの勧告があるかどうかです。**構成**は ColimaUI がイメージ自体に当てる
ルールです。どの権限で動くのか、どこから来たのか、どれだけ古いのか。完全にパッチ
済みでも構成が悪いイメージはあり得ます。スコアが一つではなく四つに分かれているのは
そのためです。

## まず直す価値のある点

**root で動かさない。** `USER` 命令がなければプロセスは uid 0 で起動します。
イメージ内にアカウントを作り、Dockerfile の最後で切り替えます。

```dockerfile
RUN adduser --system --no-create-home app
USER app
```

ポート 80 が必要なら、コンテナ内では 8080 を待ち受け、外側で `-p 80:8080` と
対応付けます。低いポートを bind する必要があること自体が、そのイメージがいまだに
root で動いている理由であることがほとんどです。

**認証情報をイメージから出す。** `ENV` にある値はイメージのすべての複製について
回り、`docker inspect` で見えます。実行時に渡してください。

```bash
docker run --env-file ./secrets.env myapp:1.2.3
```

値を消してビルドし直すだけでは足りません。その値を含んでいたレイヤーは、push 済み
のレジストリに残ります。認証情報自体をローテーションしてください。

**デプロイ対象を固定する。** タグはイメージではなく位置です。`latest` も `stable`
も、さらには `1.27` も、パッチが出れば publish し直されます。リリースには完全な
バージョンを付け、重要な場所ではダイジェストでデプロイします。

```bash
docker pull nginx@sha256:...
```

**定期的に再ビルドする。** ベースイメージのパッケージ更新は続きます。半年再ビルド
していないイメージは、ビルド後に公開された修正を含みようがありません。今日のスキャン
結果がどれほどきれいでも同じです。

**出所を記録する。** 二つのラベルが、素性の分からないイメージを追跡可能なものに
変えます。

```dockerfile
LABEL org.opencontainers.image.source="https://github.com/you/app"
LABEL org.opencontainers.image.revision="$GIT_SHA"
```

## 小さくすることは、たいてい安全にすること

検出の多くは、アプリケーションが一度も呼ばないパッケージから来ます。`-slim` や
`-alpine` のベース、あるいはビルド成果物だけを載せるマルチステージビルドは、それら
とともに「パッチを当てる理由」も取り除きます。セキュリティページは主要なベース
イメージについて代替候補を示します。

置き換えで何が変わるかは把握してください。Alpine は glibc ではなく musl を使うため
ネイティブ依存の再ビルドが要ることがあり、distroless にはシェルがありません。
それこそが安全である理由であり、同時に内部でのデバッグが難しい理由です。

## スコアについて

数値は一覧を並べ替えるためのものです。答えは四つの内訳にあります。問題が CVE なのか、
構成なのか、来歴なのか、古さなのか——必要な作業はそれぞれ違います。

スコアは、同じスキャナー・同じ脆弱性データベースの日付・同じルールパック版で計算
されたスコアとだけ比較できます。だから三つとも数値の隣に印字しています。異なる
スキャナーは同じイメージで十倍以上食い違うことがあります。これは脆弱性データの
性質であって、どちらかの不具合ではありません。

## 厳格さのレベル

L1 はほぼすべてのイメージが満たすべき内容です。L2 は多くのサービスにとって妥当な
推奨を加えます。L3 は厳格で、その一部は個々のイメージには当てはまりません。レベル
を上げるとスコアは下がることしかありません。ルールが増えるだけで、減ることはない
からです。

## ルールの出どころ

ColimaUI のルールは本プロジェクトが書いています。公開された標準の項番（例: CIS
Docker Benchmark §4.1）を参照して原典を追えるようにしていますが、文言・採点・助言は
私たちのものです。ColimaUI は CIS や OWASP の認定・提携・推奨を受けていません。
