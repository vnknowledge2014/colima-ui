# Colima 上的蜜罐

## 什么是蜜罐

蜜罐是一种只为被攻击而存在的服务。不会有任何正当流量连接它，因此它记录到的每一
次连接，按定义都是你意料之外的东西。这就是它的全部要点：不会有来自正常流量的误
报，因为根本不存在正常流量。

容器让蜜罐在本地运行变得实际可行。每个蜜罐都是一个用完即弃的进程，拥有自己的文
件系统，而 Colima 本来就把它们关在一台虚拟机里。

## 两种截然不同的运行目的

请明确你在做哪一种，因为二者的风险性质正好相反。

**为了学习。** 在自己的机器上运行，绑定到 localhost，自己连上去看看日志长什么
样。没有任何恶意流量会到达它。这是安全的，也是这些文章所描述的用法。

**为了检测。** 把它放在一个本不该有任何东西触碰的网络里，把任何命中都当作真实
信号。这确实有用，也确实有后果——在靠近它之前请先读下面的警告。

## 暴露到真实网络之前

这些不是走过场的提醒。

- **放在公网上的蜜罐会把恶意流量吸引到你的 IP 地址上。** 这正是它的职责。你是
  在主动选择成为目标，而且这些流量不会因为你失去兴趣就停止。
- **先确认你所在单位的政策。** 在企业网络中，运行一个伪装成基础设施的服务，即
  使你的意图是防御性的，也可能违反政策。请事先询问，而不是事后。
- **你的主机服务商可能也有规定。** 有些明确禁止，有些要求提前报备。
- **被攻陷的蜜罐是一个跳板。** 这些服务是刻意做得脆弱的。一旦有人突破出来，攻
  击者就已经在你所放置的那个网络内部了。

这些文章里的每个 compose 文件都绑定到 `127.0.0.1`，原因就在于此。如果你把它改
成 `0.0.0.0`，那是一个决定——请有意识地做出它。

## 从哪里开始

先读 **使用 Cowrie 的 SSH 蜜罐**。它的日志最容易读懂，而且你用一条命令就能自己
制造流量，因此在决定是否走得更远之前，你可以先看到整个流程跑通。

**使用 OpenCanary 的诱饵服务** 更接近它们在真实检测中的用法：在被触碰之前一直
保持安静。

**读懂蜜罐日志** 讲的是有了输出之后该做什么。
