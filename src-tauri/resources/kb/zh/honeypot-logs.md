# 读懂蜜罐日志

## 唯一的规则

蜜罐的日志条目不是需要过滤掉的噪音。没有任何正当流量会连接蜜罐，因此每一条记录
都意味着有东西碰了一个本不该被碰的服务。把数量当作信号，而不是当作需要调优消除
的问题。

这和你读应用日志的方式正好相反，也正是蜜罐值得运行的原因。

## 在依据日志采取行动之前

蜜罐日志记录的是攻击者对自己的声称，而这些声称伪造起来很便宜。

- **来源地址经常是伪造的或借用的。** 打到你这里的 IP 往往是一台被攻陷的第三方
  主机，而不是操作者本人。不要反击，不要反向扫描，也不要把它加进一个你难以撤销
  的封禁列表。
- **被下载进蜜罐的文件是敌意文件。** Cowrie 会保存攻击者试图下载的东西。不要出
  于好奇在自己的机器上打开、运行或解压它们。
- **不要公开原始日志。** 里面含有第三方地址，有时还有从真实泄露事件中重复使用的
  凭据。分享前请先脱敏。

## 在 ColimaUI 中观察

这些文章里的蜜罐都是普通的 Compose 项目，所以你已有的工具都能直接用：

- **Compose 页面** — 找到项目，打开服务，不用离开应用就能读日志。这是实时观察一
  个会话最快的方式。
- **Containers 页面** — 确认蜜罐确实在运行，以及已经运行了多久。
- **Activity 页面** — CPU 和内存随时间的变化。一个蜜罐突然开始真正消耗 CPU，这
  件事本身就值得调查：说明有东西做的事情已经不只是敲门了。

## 该关注什么

**尝试过的凭据。** 攻击者使用的用户名和密码清单，能告诉你对方以为你是谁。清一色
是路由器默认密码，说明你只是被无差别扫描到了；如果你真实应用的用户名出现在里面，
说明有东西是冲着你来的。

**执行过的命令。** 在 Cowrie 里，登录后的第一条命令信息量最大。`uname -a` 是侦
察。指向某个 IP 地址的 `wget` 或 `curl` 是在尝试拉取载荷——而它请求的那个 URL，
就是你可以据此行动的具体情报。

**重复性。** 同一个来源地址反复回来，和一千个只连一次的连接是两回事。后者是互联
网的背景噪音，前者是有人注意到了你。

**时间分布。** 你暴露一个服务几分钟后命中集中涌入，说明是被大规模扫描发现了。这
在公网地址上很正常，它不能说明你的安全状况如何——只能说明互联网很忙。

## 保留输出

两个蜜罐都会在人类可读日志之外，同时写出结构化 JSON：

```bash
# Cowrie —— 先复制出来，再在宿主机上读。
docker compose -f cowrie-compose.yml cp \
  cowrie:/cowrie/cowrie-git/var/log/cowrie/cowrie.json ./cowrie.json
tail -20 cowrie.json
```

用 `cp` 而不是 `exec cat` 不是风格偏好：Cowrie 镜像里既没有 shell 也没有 `cat`，
所以 `exec` 会以 `executable file not found` 失败。`cp` 走守护进程，不依赖容器
内的任何东西。

如果你打算让蜜罐运行得比一次演示更久，请定期把那个文件复制出去。容器日志会轮转，
数据卷会被清理；只有留存下来的记录才有价值。

## 什么时候该停

如果你是为了了解蜜罐怎么工作才启动它的，那么在完整看过一个会话之后就把它停掉。
一个没人读它输出、却一直在运行的服务不叫检测——它只是你机器上多出来的、一个会应
答网络的东西。
